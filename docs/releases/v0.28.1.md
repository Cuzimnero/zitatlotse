# Zitatlotse 0.28.1 — startup readiness correction

Local test candidate; not published.

The setup wait loop previously required the `nsIProcess` installer-exit callback before releasing the shared startup promise. If that callback is delayed, settings, index status and search requests remain blocked even when the current local worker is already healthy.

The loop now independently checks the local worker. It releases preparation once `/health` identifies Zitatlotse with the candidate's exact version. An old worker or an unrelated server does not satisfy this check. Existing installer errors, bounded waits and retry behavior remain in place.

Once setup reaches the starting phase, an unresponsive worker produces an actionable error after one minute. The complete setup also has a ten-minute wall-clock limit. A later attempt can retry; no database rebuild is involved.

A regression reproduces the stalled 90% starting state with a healthy worker and a missing process-exit callback. It fails before the correction and passes afterwards, including a dependent service request. The packaged runtime test now extracts the setup script from the finished XPI.

This includes both search-speed options from 0.28.0 and the earlier resource-loading correction. PDFs, model weights, quotations and settings do not require rebuilding.
